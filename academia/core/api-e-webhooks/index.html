API e webhooks

Ligue o Jarvis à loja virtual, ao BI ou ao ERP do cliente com segurança: cada sistema ganha a própria chave, só com o que precisa, de onde pode chamar e até quando vale; o Jarvis avisa o outro sistema na hora em que algo acontece, com o conteúdo assinado; e cada chamada fica registrada.

Lição 33.1

Chaves de API

Configurações › Configurar › Chaves de API

Para que serve

Cada sistema com a própria chave: os escopos (clientes, produtos, estoque, pedidos para ler ou criar, títulos, notas com o XML, ordens de produção e entregas), os IPs liberados, a validade e o limite por minuto. A chave aparece uma vez só: o banco guarda só o resumo dela.

Quando usar

A cada sistema novo que vai conversar com o Jarvis.

Passo a passo

  1. Clique em Nova chave (F7) e dê o nome do sistema.
  2. Escolha os escopos (há pacotes prontos: loja virtual, BI só leitura, só estoque).
  3. Informe os IPs liberados (se o outro sistema tem IP fixo), a validade e o limite por minuto.
  4. Copie a chave (começa com jva_) direto para o outro sistema.
  5. Para trocar, use a troca com convivência (a antiga vale por algumas horas); para a que vazou, revogue com o motivo.
Exemplo com a Loja Modelo

A loja virtual fictícia da Loja Modelo lê produtos, estoque e clientes e cria pedidos; o BI da contabilidade só lê, e só da rede dele.

Dicas
  • A chave fica suspensa sozinha se quem a criou deixar de ser dono ou administrador da empresa.
Cuidados
  • Nunca mande a chave por e-mail nem guarde em planilha. Chave que cria pedidos sem IP liberado aparece no aviso da tela.

Lição 33.2

Webhooks

Configurações › Configurar › Webhooks

Para que serve

O Jarvis avisa o seu sistema na hora em que algo acontece — pedido criado, faturado, entregue ou cancelado, título pago, nota autorizada ou cancelada, entrega concluída ou com ocorrência, estoque abaixo do mínimo, produção concluída —, com o conteúdo assinado (HMAC-SHA256). Se o outro sistema não responder 2xx em 10 segundos, o Jarvis tenta de novo sozinho, cada vez esperando mais.

Quando usar

Quando o outro sistema precisa saber das coisas sem ficar perguntando.

Passo a passo

  1. Clique em Novo webhook (F7): o endereço https e os eventos.
  2. Copie o segredo (começa com whsec_); ele aparece uma vez.
  3. Clique em Testar envio e confira a resposta na lista de entregas.
  4. Se o outro sistema ficou fora do ar, corrija e use Reenviar ou Entregar agora.
  5. Para trocar o segredo, Trocar segredo: os dois assinam juntos por 24 horas.
Exemplo com a Loja Modelo

O ERP do atacadista fictício está respondendo 503 há várias tentativas: o webhook pausa sozinho depois de 50 falhas seguidas, e a tela mostra a resposta de cada tentativa.

Dicas
  • A tela traz o código pronto para o outro sistema conferir a assinatura (o cabeçalho Jarvis-Assinatura).
  • Nas Automações, a ação "chamar um webhook" só aceita um endereço cadastrado e ligado aqui.
Cuidados
  • Só endereços https públicos: rede interna, localhost e IP privado são recusados, no cadastro e na hora do envio.

Lição 33.3

Registro de chamadas

Configurações › Configurar › Registro de chamadas

Para que serve

Cada chamada dos últimos 90 dias: a chave, a rota, a resposta, o tempo, os registros, o IP e o X-Request-Id; o uso por chave e por rota e o aviso das chamadas de IP não liberado.

Quando usar

Quando o outro sistema reclama de erro e para acompanhar o uso.

Passo a passo

  1. Leia Chamadas em 24 h, Deram certo, Tempo médio e Recusadas.
  2. Procure pelo X-Request-Id que o outro sistema recebeu.
  3. Veja o uso por chave e por rota para achar quem chama demais.
Exemplo com a Loja Modelo

Duas chamadas do BI vieram de um IP fora da rede liberada e foram recusadas: o aviso sugere trocar a chave se não foi uma mudança de servidor.

Dicas
  • O registro guarda a rota em modelo, sem o identificador e sem a consulta: nada de dado sensível no log.
Cuidados
  • Chamada de IP não liberado repetida pode ser uma cópia da chave: troque-a.

Lição 33.4

Documentação da API

Configurações › Configurar › Documentação da API

Para que serve

A API REST do Jarvis ERP em OpenAPI 3.1: o endereço, como entrar com a chave, a paginação por cursor, o limite por minuto, o POST que não duplica com a Idempotency-Key, os erros no padrão RFC 7807, os recursos com os exemplos e os eventos dos webhooks.

Quando usar

Para entregar ao desenvolvedor do outro sistema.

Passo a passo

  1. Copie o endereço com Copiar o endereço.
  2. Procure o recurso (ex.: Pedidos de venda) e leia os campos, os filtros e o exemplo.
  3. Clique em Baixar openapi.json e mande o arquivo ao desenvolvedor.
Exemplo com a Loja Modelo

A loja virtual cria o pedido com o código do produto e o documento do cliente: o Jarvis acha o preço pela tabela do cliente, aplica a alçada de desconto de Vendas e numera como os outros pedidos.

Dicas
  • Para sincronizar, peça ?alterado_desde= com o último alterado que você guardou e siga o proximo_cursor.
Cuidados
  • A chave é de servidor para servidor: não a coloque no código de uma página que roda no navegador do cliente.
Pratique agora na demonstração
Exercício

Pratique na demonstração

  1. Crie uma chave "Teste BI" só com produtos:ler e estoque:ler, válida por 30 dias.
  2. No webhook da loja virtual, clique em Testar envio.
  3. Na documentação, procure Estoque e leia o filtro abaixo_minimo.
Confira

A chave nova aparece na lista com o prefixo jva_ e os dois escopos, e o teste do webhook aparece nas entregas.
